# 写作原理：深层方法

本文件是 `SKILL.md` 的扩展。核心执行文件负责"怎么做"，本文件解释"为什么"以及每一层机制如何展开。需要深入打磨时才读取。

阅读顺序：先理解 Reader State（上层控制模型），再理解 Unbuyable Gap（故事的核心），最后理解六类 Evidence（落地手段）。

---

## 1. Reader State 深入解释

Reader State 是本 Skill 的上层控制模型。写作的每一个决策——选哪个细节、用什么数字、让谁说话、在哪里收尾——都应该先回答：这条信息要把读者从什么状态带到什么状态？

四个状态：

### K = Knowledge

读者现在知道什么？

- 读者知道的，往往多于叙述者说出来的（见 Information Gap）。
- 给读者一条新信息时问自己：它改变了读者对谁、对什么、对什么时候的理解？

### J = Judgment

读者现在如何判断人物？

读者会在极短时间内给人物贴标签：这个人被蒙在鼓里、这个人什么都肯答应、这个人只在乎钱。标签一旦贴上，就会一直起作用，直到被一次行为翻转。

写作的核心工作之一，是管理这个判断，并且决定在哪个位置翻转它（见 Reader Judgment Flip）。

### E = Expectation

读者期待接下来发生什么？

期待来自节奏、重复、类型惯例。重复一个动作十几次，读者就会期待它继续；期待被打破的那一刻，就是事件。

管理期待不是防止读者猜到，而是让读者的猜测显得有价值：猜对了，确认关系；猜错了，就是转折。

### T = Tension

当前情绪张力应该增加还是释放？

- 加压：追加细节、加密数字、延续重复、拉长清单。
- 释放：切断场景、收走物件、让句子忽然变短。

张力不是越高越好。好的克制叙事会在你想听到结论的地方关掉声音。

### 一条信息改变一个状态

这是最低门槛。检查每一条重要信息：

```text
这条信息改变了 K / J / E / T 中的哪一个？
如果一个都不改变 → 删除，或改造到改变为止。
```

注意：一条信息可以同时改变多个状态，但**不能一个都不改变**。只为了让读者"感受氛围"而存在的信息，通常就是无功能氛围句。

## 2. Reader Judgment Flip

读者对人物的判断由行为事实驱动，不是由形容词驱动。判断可以被建立，也可以被一次行为推翻。

### 建立判断

用连续性建立判断：同样的事件发生一次是偶然，发生三次就是性格。

- 三次都由助理处理她的请求 → 读者建立"他用系统代替到场"的判断。
- 三次他都付了钱 → 读者建立"他用金额回应一切"的判断。

### 翻转判断（Judgment Flip）

在最熟练的动作上安排一次意外。翻转点通常是 Unbuyable Request 或 Pattern Break。

判断被翻转时不需要解释，解释会削弱翻转的力度。读者看到行为事实，自己完成翻转，记忆最深。

### 不要机械翻转

翻转必须由角色的性格和处境自然产生，不能为了让读者"没想到"而突然变一个人。读者必须能复盘这个翻转——回看时觉得"其实一直有迹象"。

## 3. Information Gap

保持一层稳定信息差：

```text
Author knows
    >
Reader knows
    >
Narrator explicitly admits
```

叙述者知道的，少于读者拼出来的。读者知道的，少于作者设计的。

### 间接渠道

信息优先从这些渠道进入故事，叙述者本人不直接说出来：

- 财务账单 / 发票 / 付款记录
- 手机提醒 / 日历
- 助理汇报
- 酒店 / 医院 / 律师的电话与通知
- 第三人的一句话
- 合同与文件
- 照片
- 未使用的物件（买了没用、拆了没送）

例子（虚构）：叙述者从不管家里的细节。读者知道家里有人离开，是因为保洁每天还会按原来的时间过来，把客厅茶几上多出来的一杯水倒掉。叙述者从不提这人是谁。信息通过保洁的行为进入读者视野，叙述者什么都没承认。

### 作者不纠正叙述者

叙述者说"房子一直这么大，一直这么空"，作者不补一句"其实他很难过"。信息差一旦被作者跳出来修复，读者就被剥夺了判断权。

## 4. Pattern / Pattern Break

Pattern 是资源叙事的地基：重复建立期待，打破制造事件。

### 建立 Pattern

选择一种可以重复的行为，重复到读者产生预期。良好 Pattern 的三要素：

- 行为具体（动作、数字、渠道都可）。
- 行为高度一致性（每次几乎一样）。
- 行为与 Unbuyable Gap 直接相关。

### Pattern Break

在最重要的时刻打破 Pattern。打破方式：

- 不解释为什么打破。
- 打破后立即继续，不回头。
- 打破点只出现一次，不要把"打破"本身变成新的 Pattern。

判断 Pattern Break 是否成功的标准：读者在打破点之前已经默认模式会继续。

### 关系 · 与 Unbuyable Gap

Pattern 展示的是"系统如何解决一切"，Pattern Break 展示的是"系统这一次解决不了"——两者服务同一个 Unbuyable Gap。没有 Pattern 就打不响 Break，没有 Break 读者就不知道系统曾经有边界。

## 5. Narrator Gap

叙述者的自我叙述与行为事实之间的落差。

```text
Narrator Believes → Observable Fact → Reader Concludes
```

- Narrator Believes：叙述者自认为的道理。
- Observable Fact：读者能直接看到的行动事实。
- Reader Concludes：读者由此得出的、叙述者自己看不见的判断。

### 三列表的使用规则

- 表格是写作时的内部模型，永远不要写进正文。
- 表格左侧使用叙述者的语言（真实、自然，不能像自嘲）。
- 表格右侧是读者自己得出的结论，作者只负责提供事实。
- 不固定使用示例行，根据主题重新生成矛盾。

### 叙述者类型的常见特征

拥有资源、对自己判断自信、在关键时刻缺席或委托他人。三特征不需要同时出现，但至少要有两个，否则落差不够。

## 6. Numbers

### 功能

- 建立尺度：让读者感知人物所处的世界有多大。
- 制造反差：两个数字并置，一句话不说也讲完了差距。
- 暴露执念：叙述者记得的每一个精确数字，都是他在意的地方。
- 改变判断：一个可信的数字可以把读者对人物的判断翻转过来。
- 推进事件：数字不是静态信息，它应该在场与场之间变化。

### 约束

- 数字必须服务画面，不为了"显得真实"而堆砌极精确的数字。
- 两个数字要能形成关系（对比、乘积、时差），否则只是装饰。
- 数字经得起基本核查：币种、面额、单位、时间线要自洽。
- 连续三场不要都用同一类数字做冷收尾。

### 常见错误

- 只写"很贵"，或只写金额不写它换来什么。
- 数字一次性地出现后不再出现，无法回收。
- 数字精确到离谱但没有任何功能。

## 7. Objects

### 核心原则

核心物件至少出现两次。再次出现时，其含义必须发生变化。

- 第一次：日常或亲密功能（物件被正常使用）。
- 中间：角色关系变化后，物件被用错、放错、找回。
- 最后一次：物件还在，使用方式已经不同。

### 选物标准

- 足够小、足够具体、可触摸。
- 与核心关系有直接接触（对方用过的、留下的、送的）。
- 能承担至少两个功能：塑造人物 + 推进事件 / 制造反差 / 埋伏笔。

### 常见错误

- 物件只在结尾临时出现，读者对它没有记忆。
- 同一物件反复出现但含义不变，变成纯背景。
- 用贵重物件代替具体物件（炫富代替叙事）。

## 8. Labor

### 功能

展示"所有事情都有人完成"。劳动让资源产生可见成本，也让缺席变得可见：既然司机、助理、保洁都在，那么"谁没来"就被衬托出来。

### 用法

- 写具体劳动，不要写"工作人员"这种抽象集合。
- 让劳动形成链条：一个请求如何被多个人接力完成。
- 让劳动暴露权力：哪些事被分配出去了，哪些事被留给了本人。

### 核心暴露

劳动承担的是"唯一没有完成的事情，只能由本人完成"——用所有被完成的事，反衬那件没被完成的事。劳动不是为了炫富。

### 常见错误

- 劳动角色只是背景道具。
- 三个以上场景用同一个劳动角色完成相同功能。
- 只写劳动不写它的成本和后果。

---

## 9. Space

### 功能

空间把"缺席"变成可见事实。空房间、空座位、没人使用的酒店房间、仍然运行的办公室和系统，是缺席的物理载体。

### 用法

- 空间要具体：有几张床、窗帘的状态、温度、灯。
- 空间的状态要有人可见地维护（保洁还能进来，说明谁拿着钥匙）。
- 空间与"仍然运行的系统"配对：房间还订着、座位还留着、系统还在执行。

### 常见错误

- 只用"空空荡荡"这种抽象词。
- 空间描写一次成景，之后不再出现在故事里。
- 空间里没人，也没有任何人在维护它（空间需要维护者才有对比）。

## 10. Transactions

### 核心思想

关系已经停止，系统可能仍然继续执行。

账单、付款、退款、押金、合同、赔偿、订阅、取消费用、工资、发票——关系结束之后，这些仍然按月发生。

### 用法

- 用交易记录推进时间线：一个订阅还在扣费，说明"上个月仍在乎"。
- 用取消费用量化决定：取消一次行程，付一次违约金。
- 用退款暴露变化：退回的东西，就是不再需要的东西。
- 交易是 Information Gap 最天然的载体：读者从账单里拼出叙述者不肯说的事。

### 常见错误

- 交易是孤立罗列，不推进任何判断。
- 交易金额与人物财富不成比例（自洽性）。
- 交易出现一次后不再回收。

---

## 11. Actions

### 功能

用动作替代心理解释。Action 是 Evidence 中最难造假的一类：叙述者可以假装感受，但很难假装动作。

### 动作对

删除 → 恢复
拿起 → 放回
打开 → 没发送
付款 → 停顿
取消 → 又保留一项
走到门口 → 没进去

### 用法

- 动作要"差半步"：差一点删除、差一点发送、差一点进门。完成的动作说明决定了什么，未完成的动作说明还有什么放不下。
- 一个动作的两次出现构成 Pattern，第三次的偏差就是 Break。
- 动作不带情绪形容词，读者从动作本身读出情绪。

### 常见错误

- 动作太完整（发完了、删干净了），没有留下未完成的空间。
- 动作前加了心理前缀（"我犹豫了一下"改为直接写停顿）。
- 动作不回收：开头捡起的东西结尾没有去处。

---

## 12. Ending Return

结尾回收开头建立的东西，且含义已经改变。

### 回收对象

数字（同一点数再出现一次）、物件（同一个物件再被使用一次）、动作（同一个动作再发生一次）、空间（同一个空间再被描述一次）。

### 判定标准

- 回收后不加解释。
- 读者自己完成"它变了"的判断。
- 结尾验收：如果删掉这个回收，开头失去了支点，结尾失去了纵深。

### 结尾不是结论

结尾不要总结人生、不要讲道理、不要走出故事宣布主题。结尾是一个具体的画面或动作，让故事在读者心里继续。

---

## 13. Technique Density

### 思想

每个场景只承担它该承担的技巧负载。技巧不是越多越好，观众记住的不是"用了多少技巧"，而是"哪个技巧真的改变了判断"。

### 密度约束

- 每个场景最多保留一句可独立传播的句子（金句密度限制）。
- 三个场景内不得共用完全相同的"数字 + 劳动 + 冷句"组合。
- 全篇比喻不超过一处。
- 长句只用于流程、服务系统、行程和物件清单，其余短句主导。

### 判断是否超载

如果删掉某一句，读者对人物和故事的判断没有变化，这一句很可能就是技巧残留。金句、数字、冷收尾都适用这个测试。
